# RBAC granular — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Autorização baseada em papéis com permissões atômicas, checagem de ownership, condições declarativas por recurso e — o ponto que nenhum concorrente cobre — autorização que funciona em listagens, não só em recurso único.

**Architecture:** O catálogo de permissões vive em código, composto a partir de blocos que cada módulo declara, e o tipo `Permission` é derivado dele — uma permissão inexistente falha no build. Papéis e concessões vivem no banco, validados contra o catálogo no boot. Um `PermissionGuard` resolve rota e recurso único; um helper `scopeFor()` traduz as mesmas condições em fragmento `where` do Prisma para listagens. Cache em Redis entra por último, como camada opcional sobre uma resolução já provada.

**Tech Stack:** Node 24, NestJS 11, TypeScript 6, Prisma 7 (com `@prisma/adapter-pg`), PostgreSQL 16, Redis 7 (ioredis), Jest, Supertest.

**Spec:** `docs/superpowers/specs/2026-09-12-nestjs-rbac-boilerplate-design.md`

**Plano anterior (pré-requisito, concluído):** `docs/superpowers/plans/2026-09-12-fundacao-e-auth.md`

```ts
import { POST_PERMISSIONS } from '../../modules/posts/posts.permissions';

/**
 * Catálogo de permissões do sistema, composto pelos blocos que cada módulo
 * declara. Para adicionar um módulo: crie `<modulo>.permissions.ts` e
 * inclua o bloco aqui.
 */
export const PERMISSIONS = {
  ...POST_PERMISSIONS,
} as const;

type Catalog = typeof PERMISSIONS;

/**
 * União literal de todas as permissões: 'post:create' | 'post:read' | ...
 *
 * É este tipo que faz `@RequirePermission('post:updaet')` falhar no build,
 * em vez de silenciosamente negar acesso em runtime.
 */
export type Permission = {
  [R in keyof Catalog & string]: `${R}:${Catalog[R][number]}`;
}[keyof Catalog & string];

export const ALL_PERMISSIONS: readonly Permission[] = Object.entries(PERMISSIONS).flatMap(
  ([resource, actions]) => (actions as readonly string[]).map((a) => `${resource}:${a}`),
) as Permission[];

const PERMISSION_SET: ReadonlySet<string> = new Set(ALL_PERMISSIONS);

/** Guarda de tipo para validar strings vindas do banco ou de configuração. */
export function isPermission(value: string): value is Permission {
  return PERMISSION_SET.has(value);
}
```

```prisma
model Role {
  id          String  @id @default(cuid())
  name        String  @unique
  description String?
  // Papéis de sistema vêm do seed e não podem ser removidos pela API:
  // apagar 'admin' por engano deixaria a aplicação sem administrador.
  isSystem    Boolean @default(false)

  // Herança simples: um papel herda de no máximo um outro. Herança múltipla
  // vira grafo com detecção de ciclo — complexidade real para um caso raro.
  inheritsId String?
  inherits   Role?   @relation("RoleHierarchy", fields: [inheritsId], references: [id])
  children   Role[]  @relation("RoleHierarchy")

  // Costura de multi-tenancy: sempre null na v1.
  tenantId String?

  grants RoleGrant[]
  users  UserRole[]

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@index([tenantId])
}

model RoleGrant {
  id     String @id @default(cuid())
  roleId String
  // Texto livre no banco porque o Prisma não referencia tipos TypeScript.
  // A proteção é a validação no boot (Task 3), que falha se houver uma
  // permissão fora do catálogo.
  permission String
  // Condição declarativa: { "ownerId": "$user.id" } ou { "status": "draft" }.
  // JSON e não função — é o que permite traduzir para `where` do Prisma e
  // rodar a autorização dentro da query, em vez de depois dela.
  condition Json?

  role Role @relation(fields: [roleId], references: [id], onDelete: Cascade)

  @@unique([roleId, permission])
  @@index([permission])
}

model UserRole {
  userId String
  roleId String

  user User @relation(fields: [userId], references: [id], onDelete: Cascade)
  role Role @relation(fields: [roleId], references: [id], onDelete: Cascade)

  createdAt DateTime @default(now())

  @@id([userId, roleId])
  @@index([roleId])
}

enum PostStatus {
  DRAFT
  PUBLISHED
}

/// Módulo de exemplo: existe para exercitar ownership e condições, e serve
/// de material para o tutorial "adicionando seu primeiro módulo".
model Post {
  id      String     @id @default(cuid())
  title   String
  body    String
  status  PostStatus @default(DRAFT)
  ownerId String
  owner   User       @relation(fields: [ownerId], references: [id], onDelete: Cascade)

  tenantId String?

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@index([ownerId])
  @@index([status])
  @@index([tenantId])
}
```

```ts
import { Injectable } from '@nestjs/common';
import { Post, Prisma } from '@prisma/client';
import { PrismaService } from '../../core/database/prisma.service';

@Injectable()
export class PostsService {
  constructor(private readonly prisma: PrismaService) {}

  create(data: { title: string; body: string; ownerId: string }): Promise<Post> {
    return this.prisma.post.create({ data });
  }

  findById(id: string): Promise<Post | null> {
    return this.prisma.post.findUnique({ where: { id } });
  }

  /**
   * `where` vem do `scopeFor()` (Task 7) e carrega a autorização de
   * listagem. Aceitar o fragmento aqui é o que mantém a regra num lugar só.
   */
  findMany(where: Prisma.PostWhereInput = {}): Promise<Post[]> {
    return this.prisma.post.findMany({ where, orderBy: { createdAt: 'desc' } });
  }

  update(id: string, data: { title?: string; body?: string }): Promise<Post> {
    return this.prisma.post.update({ where: { id }, data });
  }

  publish(id: string): Promise<Post> {
    return this.prisma.post.update({ where: { id }, data: { status: 'PUBLISHED' } });
  }

  delete(id: string): Promise<Post> {
    return this.prisma.post.delete({ where: { id } });
  }
}
```

```ts
import { Injectable, Logger, OnApplicationBootstrap } from '@nestjs/common';
import { PrismaService } from '../database/prisma.service';
import { isPermission } from './permissions';

/**
 * Confere, no boot, que toda concessão no banco aponta para uma permissão que
 * existe no catálogo.
 *
 * Pega dois erros que de outra forma seriam silenciosos: typo numa concessão
 * criada à mão, e permissão renomeada em código sem migrar as linhas do banco.
 * Nos dois casos o efeito em runtime seria acesso negado sem explicação.
 */
@Injectable()
export class PermissionCatalogValidator implements OnApplicationBootstrap {
  private readonly logger = new Logger(PermissionCatalogValidator.name);

  constructor(private readonly prisma: PrismaService) {}

  async onApplicationBootstrap(): Promise<void> {
    await this.validate();
  }

  async validate(): Promise<void> {
    const grants = await this.prisma.roleGrant.findMany({
      select: { permission: true, role: { select: { name: true } } },
    });

    const orphans = grants.filter((g) => !isPermission(g.permission));

    if (orphans.length > 0) {
      const detail = orphans.map((o) => `  - "${o.permission}" no papel "${o.role.name}"`).join('\n');

      throw new Error(
        `Permissões que não existem no catálogo:\n${detail}\n\n` +
          'Corrija a concessão no banco ou declare a permissão no bloco do módulo ' +
          '(<modulo>.permissions.ts) e componha em src/core/rbac/permissions.ts.',
      );
    }

    this.logger.log(`Catálogo de permissões validado: ${grants.length} concessões conferidas`);
  }
}
```

Criar `src/core/rbac/permissions.service.ts`:

```ts
import { Injectable } from '@nestjs/common';
import { PrismaService } from '../database/prisma.service';
import type { Condition, ResolvedPermissions } from './permission.types';
import { isPermission, type Permission } from './permissions';

@Injectable()
export class PermissionsService {
  constructor(private readonly prisma: PrismaService) {}

  /**
   * Monta o conjunto efetivo de permissões do usuário: os papéis diretos,
   * mais tudo que eles herdam, com as condições anexadas.
   *
   * Papéis somam acesso e nunca subtraem. Por isso uma concessão sem condição
   * absorve as condicionais da mesma permissão — restringir depois de já ter
   * concedido irrestritamente não faria sentido.
   */
  async resolve(userId: string): Promise<ResolvedPermissions> {
    const directRoles = await this.prisma.userRole.findMany({
      where: { userId },
      select: { roleId: true },
    });

    const roleIds = await this.expandHierarchy(directRoles.map((r) => r.roleId));

    if (roleIds.length === 0) {
      return new Map();
    }

    const grants = await this.prisma.roleGrant.findMany({
      where: { roleId: { in: roleIds } },
      select: { permission: true, condition: true },
    });

    const resolved: ResolvedPermissions = new Map();

    for (const grant of grants) {
      // Concessão cuja permissão saiu do catálogo é ignorada aqui. O boot já
      // recusa subir nesse estado (Task 3); isto protege o caso de a linha
      // aparecer com a aplicação no ar.
      if (!isPermission(grant.permission)) {
        continue;
      }

      const condition = (grant.condition as Condition | null) ?? null;
      const current = resolved.get(grant.permission) ?? [];

      // Já é irrestrita: nada a acrescentar.
      if (current.includes(null)) {
        continue;
      }

      if (condition === null) {
        resolved.set(grant.permission, [null]);
        continue;
      }

      current.push(condition);
      resolved.set(grant.permission, current);
    }

    return resolved;
  }

  async has(userId: string, permission: Permission): Promise<boolean> {
    return (await this.resolve(userId)).has(permission);
  }

  /**
   * Expande a hierarquia seguindo `inheritsId` para cima.
   *
   * O Set de visitados não é otimização: sem ele, uma hierarquia com ciclo
   * (que o schema não impede) trava o processo em laço infinito.
   */
  private async expandHierarchy(roleIds: string[]): Promise<string[]> {
    const visited = new Set<string>();
    let frontier = roleIds;

    while (frontier.length > 0) {
      const novel = frontier.filter((id) => !visited.has(id));
      novel.forEach((id) => visited.add(id));

      if (novel.length === 0) {
        break;
      }

      const parents = await this.prisma.role.findMany({
        where: { id: { in: novel }, inheritsId: { not: null } },
        select: { inheritsId: true },
      });

      frontier = parents.map((p) => p.inheritsId!).filter((id) => !visited.has(id));
    }

    return [...visited];
  }
}
```

```ts
import { SetMetadata, type CustomDecorator } from '@nestjs/common';
import type { Permission } from './permissions';

export const PERMISSION_KEY = 'requiredPermission';

export interface PermissionMetadata {
  permission: Permission;
  /** Nome do recurso no registry, quando a checagem depende de carregá-lo. */
  resource?: string;
  /** Parâmetro de rota que contém o id do recurso. Default: 'id'. */
  param?: string;
}

/**
 * Exige uma permissão para acessar a rota.
 *
 * Sem `resource`, a checagem é apenas "o usuário tem esta permissão?".
 * Com `resource`, o guard carrega o recurso e avalia as condições da
 * concessão contra ele — é assim que ownership funciona (Task 6).
 */
export const RequirePermission = (
  permission: Permission,
  options: Omit<PermissionMetadata, 'permission'> = {},
): CustomDecorator =>
  SetMetadata<string, PermissionMetadata>(PERMISSION_KEY, { permission, ...options });
```

```ts
import { CanActivate, ExecutionContext, ForbiddenException, Injectable } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { User } from '@prisma/client';
import { PERMISSION_KEY, type PermissionMetadata } from './require-permission.decorator';
import { PermissionsService } from './permissions.service';

@Injectable()
export class PermissionGuard implements CanActivate {
  constructor(
    private readonly reflector: Reflector,
    private readonly permissions: PermissionsService,
  ) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const metadata = this.reflector.getAllAndOverride<PermissionMetadata | undefined>(
      PERMISSION_KEY,
      [context.getHandler(), context.getClass()],
    );

    // Rota sem @RequirePermission não é assunto deste guard: a autenticação
    // já foi resolvida pelo JwtAuthGuard.
    if (!metadata) {
      return true;
    }

    const request = context.switchToHttp().getRequest<{ user?: User }>();
    const user = request.user;

    if (!user) {
      throw new ForbiddenException('Acesso negado');
    }

    const resolved = await this.permissions.resolve(user.id);

    if (!resolved.has(metadata.permission)) {
      throw new ForbiddenException('Acesso negado');
    }

    return true;
  }
}
```

```ts
import type { Condition } from './permission.types';
import { USER_ID_PLACEHOLDER } from './permission.types';

/** Lê `author.teamId` em `{ author: { teamId } }`. Um nível de profundidade. */
function readPath(resource: Record<string, unknown>, path: string): unknown {
  if (!path.includes('.')) {
    return resource[path];
  }

  const [head, tail] = path.split('.', 2);
  const nested = resource[head];

  if (nested === null || typeof nested !== 'object') {
    return undefined;
  }

  return (nested as Record<string, unknown>)[tail];
}

/**
 * Avalia uma condição contra um recurso já carregado.
 *
 * Todas as chaves precisam bater (conjunção). A comparação é estrita: um
 * `'10'` de query string não vira `10`, porque coerção silenciosa em decisão
 * de autorização é fonte de falso positivo.
 */
export function evaluateCondition(
  condition: Condition,
  resource: Record<string, unknown>,
  userId: string,
): boolean {
  return Object.entries(condition).every(([path, expected]) => {
    const wanted = expected === USER_ID_PLACEHOLDER ? userId : expected;
    return readPath(resource, path) === wanted;
  });
}
```

```ts
import { Injectable, NotFoundException } from '@nestjs/common';

export type ResourceLoader = (id: string) => Promise<Record<string, unknown> | null>;

/**
 * Diz ao guard como carregar cada recurso protegido.
 *
 * Cada módulo registra o seu no `onModuleInit`, o que evita que o core
 * conheça os módulos de domínio — o acoplamento fica na direção certa.
 */
@Injectable()
export class ResourceRegistry {
  private readonly loaders = new Map<string, ResourceLoader>();

  register(name: string, loader: ResourceLoader): void {
    this.loaders.set(name, loader);
  }

  async load(name: string, id: string): Promise<Record<string, unknown> | null> {
    const loader = this.loaders.get(name);

    if (!loader) {
      // Erro de programação, não do usuário: @RequirePermission aponta para um
      // recurso que ninguém registrou.
      throw new Error(
        `Recurso "${name}" não registrado no ResourceRegistry. ` +
          'Registre-o no onModuleInit do módulo correspondente.',
      );
    }

    return loader(id);
  }

  has(name: string): boolean {
    return this.loaders.has(name);
  }
}

export { NotFoundException };
```

```ts
import {
  CanActivate,
  ExecutionContext,
  ForbiddenException,
  Injectable,
  NotFoundException,
} from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { User } from '@prisma/client';
import { evaluateCondition } from './condition.evaluator';
import { CURRENT_RESOURCE } from './current-resource.decorator';
import { PermissionsService } from './permissions.service';
import { PERMISSION_KEY, type PermissionMetadata } from './require-permission.decorator';
import { ResourceRegistry } from './resource-registry';

@Injectable()
export class PermissionGuard implements CanActivate {
  constructor(
    private readonly reflector: Reflector,
    private readonly permissions: PermissionsService,
    private readonly resources: ResourceRegistry,
  ) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const metadata = this.reflector.getAllAndOverride<PermissionMetadata | undefined>(
      PERMISSION_KEY,
      [context.getHandler(), context.getClass()],
    );

    if (!metadata) {
      return true;
    }

    const request = context.switchToHttp().getRequest<
      { user?: User; params?: Record<string, string> } & Record<string, unknown>
    >();
    const user = request.user;

    if (!user) {
      throw new ForbiddenException('Acesso negado');
    }

    const conditions = (await this.permissions.resolve(user.id)).get(metadata.permission);

    if (!conditions) {
      throw new ForbiddenException('Acesso negado');
    }

    // Concessão irrestrita: nada a avaliar contra o recurso.
    if (conditions.includes(null)) {
      // Ainda assim carrega o recurso quando a rota pede, para injetar no
      // handler e devolver 404 coerente.
      if (metadata.resource) {
        request[CURRENT_RESOURCE] = await this.loadOrFail(metadata, request.params ?? {});
      }
      return true;
    }

    // Só há condições, e não há recurso para avaliá-las: negar é o correto.
    // Uma concessão condicional não autoriza uma rota que não carrega recurso.
    if (!metadata.resource) {
      throw new ForbiddenException('Acesso negado');
    }

    const resource = await this.loadOrFail(metadata, request.params ?? {});

    // Basta uma condição satisfeita: papéis somam acesso.
    const allowed = conditions.some(
      (condition) => condition !== null && evaluateCondition(condition, resource, user.id),
    );

    if (!allowed) {
      throw new ForbiddenException('Acesso negado');
    }

    request[CURRENT_RESOURCE] = resource;
    return true;
  }

  private async loadOrFail(
    metadata: PermissionMetadata,
    params: Record<string, string>,
  ): Promise<Record<string, unknown>> {
    const id = params[metadata.param ?? 'id'];
    const resource = await this.resources.load(metadata.resource!, id);

    if (!resource) {
      throw new NotFoundException('Recurso não encontrado');
    }

    return resource;
  }
}
```

```ts
import type { Condition } from './permission.types';
import { USER_ID_PLACEHOLDER } from './permission.types';

/**
 * Traduz uma condição declarativa em fragmento `where` do Prisma.
 *
 * É o que permite a autorização rodar dentro da query, em vez de filtrar a
 * lista depois de buscá-la — filtrar depois quebraria paginação e vazaria a
 * contagem de registros que o usuário não pode ver.
 *
 * Suporta campo plano e um nível de relação. Profundidade maior lança erro
 * explícito: um filtro silenciosamente errado numa decisão de autorização é
 * pior que uma falha ruidosa.
 */
export function conditionToPrisma(
  condition: Condition,
  userId: string,
): Record<string, unknown> {
  const where: Record<string, unknown> = {};

  for (const [path, expected] of Object.entries(condition)) {
    const value = expected === USER_ID_PLACEHOLDER ? userId : expected;
    const segments = path.split('.');

    if (segments.length === 1) {
      where[path] = value;
      continue;
    }

    if (segments.length > 2) {
      throw new Error(
        `Condição "${path}" tem mais de um nível de relação. ` +
          'O scopeFor da v1 suporta campo plano e um nível (ex.: "author.teamId"). ' +
          'Reescreva a condição ou desnormalize o campo no recurso.',
      );
    }

    const [relation, field] = segments;
    const nested = (where[relation] as Record<string, unknown> | undefined) ?? {};
    nested[field] = value;
    where[relation] = nested;
  }

  return where;
}
```

```ts
  /**
   * Devolve o fragmento `where` que restringe uma listagem ao que o usuário
   * pode ver.
   *
   * - sem a permissão            → `null` (o chamador não deve retornar nada)
   * - permissão irrestrita       → `{}`
   * - uma condição               → o filtro daquela condição
   * - várias condições           → `{ OR: [...] }`, porque papéis somam acesso
   *
   * O `null` é deliberadamente diferente de `{}`: confundir os dois faria uma
   * listagem sem permissão devolver a tabela inteira.
   */
  async scopeFor(
    userId: string,
    permission: Permission,
  ): Promise<Record<string, unknown> | null> {
    const conditions = (await this.resolve(userId)).get(permission);

    if (!conditions) {
      return null;
    }

    if (conditions.includes(null)) {
      return {};
    }

    const filters = conditions
      .filter((c): c is Condition => c !== null)
      .map((c) => conditionToPrisma(c, userId));

    if (filters.length === 1) {
      return filters[0];
    }

    return { OR: filters };
  }
```

```ts
import { Injectable, Logger, OnModuleDestroy, OnModuleInit } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import Redis from 'ioredis';
import type { Env } from '../config/env.schema';
import type { Condition, ResolvedPermissions } from './permission.types';
import type { Permission } from './permissions';

const KEY_PREFIX = 'rbac:perms:';

/**
 * Cache do conjunto efetivo de permissões.
 *
 * Opcional por desenho: com RBAC_CACHE_ENABLED=false tudo funciona sem Redis.
 * Uma falha do Redis também não derruba a autorização — o erro vai para o log
 * e a resolução cai no banco. Autorização indisponível é pior que lenta.
 */
@Injectable()
export class PermissionsCacheService implements OnModuleInit, OnModuleDestroy {
  private readonly logger = new Logger(PermissionsCacheService.name);
  private client?: Redis;

  constructor(private readonly config: ConfigService<Env, true>) {}

  private get enabled(): boolean {
    return this.config.get('RBAC_CACHE_ENABLED', { infer: true });
  }

  onModuleInit(): void {
    if (!this.enabled) {
      this.logger.log('Cache de permissões desligado (RBAC_CACHE_ENABLED=false)');
      return;
    }

    this.client = new Redis(this.config.get('REDIS_URL', { infer: true }), {
      maxRetriesPerRequest: 1,
      lazyConnect: false,
    });

    this.client.on('error', (error: Error) => {
      this.logger.warn(`Redis indisponível, caindo no banco: ${error.message}`);
    });
  }

  async onModuleDestroy(): Promise<void> {
    await this.client?.quit();
  }

  async get(userId: string): Promise<ResolvedPermissions | null> {
    if (!this.client) {
      return null;
    }

    try {
      const raw = await this.client.get(KEY_PREFIX + userId);
      if (raw === null) {
        return null;
      }

      const entries = JSON.parse(raw) as [Permission, (Condition | null)[]][];
      return new Map(entries);
    } catch (error) {
      this.logger.warn(`Falha ao ler o cache: ${(error as Error).message}`);
      return null;
    }
  }

  async set(userId: string, resolved: ResolvedPermissions): Promise<void> {
    if (!this.client) {
      return;
    }

    try {
      const ttl = this.config.get('RBAC_CACHE_TTL_SECONDS', { infer: true });
      await this.client.set(
        KEY_PREFIX + userId,
        JSON.stringify([...resolved.entries()]),
        'EX',
        ttl,
      );
    } catch (error) {
      this.logger.warn(`Falha ao gravar no cache: ${(error as Error).message}`);
    }
  }

  async invalidateUser(userId: string): Promise<void> {
    try {
      await this.client?.del(KEY_PREFIX + userId);
    } catch (error) {
      this.logger.warn(`Falha ao invalidar o cache: ${(error as Error).message}`);
    }
  }

  /**
   * Usado quando um papel muda: descobrir exatamente quais usuários são
   * afetados exigiria percorrer a hierarquia inteira, e errar nessa conta
   * deixa permissão revogada ainda valendo.
   */
  async invalidateAll(): Promise<void> {
    if (!this.client) {
      return;
    }

    try {
      const keys = await this.client.keys(KEY_PREFIX + '*');
      if (keys.length > 0) {
        await this.client.del(...keys);
      }
    } catch (error) {
      this.logger.warn(`Falha ao limpar o cache: ${(error as Error).message}`);
    }
  }
}
```

```ts
import { INestApplication } from '@nestjs/common';
import { DocumentBuilder, SwaggerModule } from '@nestjs/swagger';

/**
 * Publica a documentação OpenAPI em /docs e o JSON em /docs-json.
 *
 * É a primeira coisa que o comprador abre depois de subir o projeto, e o que
 * economiza o trabalho de descrever a API à mão.
 */
export function setupSwagger(app: INestApplication): void {
  const config = new DocumentBuilder()
    .setTitle('API')
    .setDescription('Autenticação e autorização com RBAC granular')
    .setVersion('1.0')
    .addBearerAuth(
      { type: 'http', scheme: 'bearer', bearerFormat: 'JWT' },
      // O nome 'bearer' é o que @ApiBearerAuth() referencia nos controllers.
      'bearer',
    )
    .build();

  const document = SwaggerModule.createDocument(app, config);
  SwaggerModule.setup('docs', app, document, {
    jsonDocumentUrl: 'docs-json',
    swaggerOptions: { persistAuthorization: true },
  });
}
```

## Critério de pronto deste plano

1. `@RequirePermission('post:updaet')` falha no build, não em runtime
2. A aplicação recusa subir com concessão apontando para permissão inexistente
3. Um usuário sem papel recebe 403 em rota protegida e lista vazia na listagem
4. Ownership funciona nos três casos: rota, recurso único e listagem
5. Dois papéis com condições diferentes somam acesso (OR), nunca subtraem
6. Hierarquia de papéis funciona em mais de um nível e não trava com ciclo
7. O `where` do `scopeFor` chega ao Prisma — o filtro roda no banco
8. `RBAC_CACHE_ENABLED=false` e Redis fora do ar não quebram a autorização
9. `/docs` documenta auth e posts, com bearer auth e o 403 nas rotas protegidas
10. `npm run lint`, `npx tsc --noEmit` e `npm run test:all` limpos
